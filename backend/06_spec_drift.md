# Stage 6: Specification Drift Audit & API Synchronization

## 6.1 OpenAPI Specification Diff & Drift Analysis (Task 6.1)

A systematic diff was performed comparing the hand-written contract (`03_openapi_original.yaml` / `05_openapi_final.yaml`) against the runtime OpenAPI schema generated by FastAPI at `/openapi.json`.

| Schema Property / Path | Contract Spec (`05_openapi_final.yaml`) | FastAPI Generated (`/openapi.json`) | Drift Category | Resolution / Status |
| :--- | :--- | :--- | :--- | :--- |
| **Error Response Envelope** | `#components/schemas/Error` on all `4xx`/`5xx` | Automatically attached via exception handlers and route decorators | **Aligned** | Unified `create_error_response()` handler formats all errors into `{"error": {"code", "message", ...}}`. |
| **`additionalProperties: false`** | Explicit on all request bodies | Enforced via `StrictBaseModel` (`model_config = ConfigDict(extra="forbid")`) | **Aligned** | Prevents extra fields from being supplied or ignored. |
| **Action Endpoints vs Methods** | `POST /bookings/{id}/check-in`, `/check-out`, `/cancel`, `/no-show` | Registered under matching POST paths | **Aligned** | Direct mapping. |
| **Money Serialization** | String representation (`"4500.00"`) | Formatted as string in Pydantic response models | **Aligned** | Avoids IEEE 754 floating-point rounding errors. |
| **Dates & Interval Boundaries** | `YYYY-MM-DD` ISO strings | `date` objects serialized to `YYYY-MM-DD` | **Aligned** | Half-open interval `[)` respected. |
| **Query Parameter Sort Whitelist** | Whitelisted enum `[check_in, -check_in, created_at, -created_at, total_amount, -total_amount]` | Pydantic / FastAPI query enum validation | **Aligned** | Rejects arbitrary column names with `422`. |

## 6.2 Route Decorator Response Code Audit (Task 6.2)

Every route handler explicitly declares its return codes in the decorator rather than documenting only `200 OK`:
- `POST /bookings`: Declares `201 Created`, `401 Unauthorized`, `403 Forbidden`, `404 Not Found`, `409 Conflict` (room unavailable), `422 Unprocessable Entity` (guest count > max occupancy).
- `POST /bookings/{id}/payments`: Declares `200 OK` (idempotent replay), `201 Created`, `401 Unauthorized`, `403 Forbidden`, `404 Not Found`, `409 Conflict` (key payload mismatch / balance exceeded), `422 Unprocessable Entity`.
- `POST /bookings/{id}/review`: Declares `201 Created`, `401 Unauthorized`, `403 Forbidden` (pre-checkout attempt), `404 Not Found`, `409 Conflict` (duplicate review), `422 Unprocessable Entity` (out of range rating).

## 6.3 Response Model Inspection (Task 6.3)

All endpoints utilize Pydantic response models. Inspection of `/docs` confirms that no route emits:

## 6.12 Authority & Drift Prevention Strategy (Task 6.12)

**The Three Descriptions of the API:**
1. `05_openapi_final.yaml` (The Design Contract)
2. FastAPI `/openapi.json` (The Code Implementation)
3. Postman Collection (The Client Test Suite)

**Which is Authoritative?**
- **The Design Contract (`05_openapi_final.yaml`) is the single source of truth.** The implementation and client collections must conform to the contract, not the other way around.

**Drift Prevention Pipeline:**
1. **Automated CI Spec Validation:** In CI/CD pipelines, run a schema linter (e.g. `openapi-spec-validator` or `spectral`) asserting that `fastapi.openapi()` matches `05_openapi_final.yaml` before merging any pull request.
2. **Contract-Driven Test Generation:** Generate automated test assertions directly from the OpenAPI spec using tools like Schemathesis, ensuring that breaking changes immediately fail the build.
3. **Automated Postman Sync:** Export and sync the Postman collection via the Postman CLI / Newman during test stages, preventing manual copy-paste drift.
